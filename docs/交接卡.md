`@dongdongxiaozu/dongjiagoushi(架构·开发) [触发:架构·开发] PKG-A：AP化学 Unit1 铺题（首批薄切片 ~20 题，跑通链路后滚铺到 ~750）`

### PR 评审 → 开发 串联工作流（代码/功能类 PR 必走）

> **目的**：本项目所有**代码/功能类**改动（改脚本、加文档/机制、改流水线等）一律先过 `架构·评审`，评审 `passed` 后再交 `架构·开发` 处理遗留 / 进入合并，避免"自己写、自己审、自己并"。铺题类 PR（纯题目 .md，CI `check.mjs` 全绿即可）不强制走评审。

**触发顺序（评审在前、开发在后）：**

1. 提交方 / 经理在 **PR 评论**中召唤评审：
   `@dongdongxiaozu/dongjiagoushi(架构·评审) [触发:架构·评审] 请评审 #<PR号>：<一句话变更范围>`
2. `架构·评审` 返回结论：
   - **passed** → 直接进下一步；**needs_modification / critical** → 评审在 PR 上留行级意见，召唤 `架构·开发` 修复后回到第 1 步复评。
3. 评审 `passed` 后，召唤开发处理 / 收口：
   `@dongdongxiaozu/dongjiagoushi(架构·开发) [触发:架构·开发] 评审已通过，请处理 PR #<PR号> 遗留事项并进入合并。`

**约定**
- 评审必须由 `架构·评审`（或平台 code-review NPC）发起，**提交者不自审**。
- 评审通过前不触发开发、不进合并；CI `check.mjs` 红灯照常阻塞合并。
- 本仓库现有角色触发语句见上文 5.1「各角色触发语句」。
